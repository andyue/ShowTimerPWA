# 區網廣播試用：現場電腦啟動，手機掃碼

不需要固定公開 IP、自己的網域、雲端帳號或路由器 port forwarding。網頁與同步服務一起由現場電腦提供。

## 第一次準備（需要外網下載）

1. 在現場電腦安裝 **[Node.js 24 官方下載](https://nodejs.org/download/release/latest-v24.x/)**。
   Windows 的 Dell 電腦選擇檔名以 `x64.msi` 結尾的安裝檔；Mac 選 `.pkg`。
2. 從 [GitHub 專案](https://github.com/andyue/ShowTimerPWA) 的 Code → Download ZIP 下載最新版本並完整解壓縮到一個資料夾。不要直接在 ZIP 裡執行。
3. Windows 雙擊 **Start-LAN-Windows.cmd**；Mac 可在終端機進入專案執行 `npm ci`，再執行 `npm run lan`（也提供 Start-LAN-Mac.command）。
4. Windows 啟動檔會在首次使用時下載套件，接著建置並啟動服務。首次下載後，日常啟動不需外網。
5. Windows 防火牆若詢問 Node.js 網路存取，只允許你信任的 **私人網路**。若 Wi-Fi 被設定成公用網路，先確認是你信任的場地網路，再於 Windows 設定改成私人網路；不必停用防火牆。

## 每次演出／測試

1. **電腦與手機連同一個區網。** 電腦可用有線、手機用 Wi-Fi，只要裝置能互相存取即可；避開訪客網路與 AP/client isolation。
2. Windows 雙擊 **Start-LAN-Windows.cmd**；或在專案目錄執行：
   ```sh
   npm run lan
   ```
3. 保留終端機視窗，在這台電腦開啟它顯示的主控網址，預設：
   ```text
   http://127.0.0.1:8789/
   ```
4. 建立段落，或匯入既有 Show File。
5. Tools 找到 **區網廣播**。若有多個 IP，選擇電腦與手機所在的 Wi-Fi／有線介面；不要選 VPN、虛擬機網卡。
6. 按 **開啟區網廣播**，用手機相機掃描 QR Code。觀看連結會包含 `192.168…`、`10.…` 或 `172.16–31.…`，不會包含 `localhost`。
7. 操作開始、暫停、恢復、換段與 Add Mark，確認手機同步。Q Mark 時間、段落與備註預設一起廣播；新增、修改與刪除都會更新，手機只能觀看。
8. 結束時先按 **停止廣播**；要關閉區網服務，在終端機按 **Ctrl+C**。

## 建議第一次實際走一次

- 開始計時，觀察兩邊秒數是否接近。
- 暫停 10 秒，確認演出時間固定、本次暫停持續增加。
- 恢復演出，再切換下一段。
- 新增 Q Mark、修改備註與刪除標記，確認手機清單同步；重新整理後仍保留完整清單。
- 手機重新整理，應回到目前狀態。
- 主控重新整理，應恢復計時與同一個觀看連結。
- 手機暫時離開 Wi-Fi 再接回，觀察斷線提示與重連。
- 保留 Wi-Fi 但中斷路由器外網，確認新手機仍能載入觀看頁並同步。
- 記下卡住的步驟，例如啟動檔、選 IP、掃碼、畫面大小；再據此調整流程。

## 已知限制與排錯

- **與線上版資料分開。** GitHub Pages 和 `127.0.0.1:8789` 是不同來源，儲存資料不同。先從線上版匯出 JSON，再在區網主控匯入。不要在演出進行中切換網址。
- **主控固定在啟動服務的電腦。** 直接開區網 IP 根網址只會顯示掃碼提示；請用主控電腦的 127.0.0.1 網址操作。
- **這版使用 HTTP／WS。** 不用安裝自簽憑證，但資料未加密，請在自己信任的區網使用。不要將 8789 埠轉發到公網。
- 手機的 HTTP 觀看頁不能使用瀏覽器 Wake Lock；請自行調整自動鎖定並保持頁面在前景。這個限制不影響計時同步。
- 若沒有偵測到私人 IPv4，先連上 Wi-Fi／網路線再重新啟動。這版不提供 IPv6-only 網路與自動探索服務。
- 連不上：先檢查相同區網、選對 IP、Windows 私人網路防火牆、Wi-Fi 用戶端隔離。固定公開 IP 設定不影響本功能。
- 看到「連線中斷」：檢查主控電腦是否休眠、終端機是否關閉，主控網頁是否仍開著。
- 更換 Wi-Fi 或電腦 IP 後，重啟區網服務，按停止廣播再重新開啟並分享新的 QR Code。
- 區網服務不保存房間到磁碟：重啟服務後舊連結失效，在主控按停止廣播再開啟即可。演出檔案與計時狀態仍由主控瀏覽器保存。
- 若 8789 已被使用，先關閉另一個服務。進階使用可透過 `LAN_PORT` 指定其他埠；主控網址也需跟著變更。
- OSC 仍需另外執行 `npm run osc:bridge`。預設已允許區網主控 `http://127.0.0.1:8789`；自訂埠時要調整 OSC 橋接的 `ALLOWED_ORIGINS`。

目前已以瀏覽器自動化與實際私人 IPv4 路徑測試；Windows 防火牆提示、實際手機相機掃碼及場地 Wi-Fi 需要你現場試用。


## 廣播主機如何更新

GitHub Pages 的部署只更新線上網站，**不會自動更新 Windows／Mac 上下載的程式**。請在演出結束後更新，主控網頁、同步服務與觀看頁要一起更新。

### 使用 Download ZIP 安裝（Windows 建議）

1. 先在主控匯出 JSON Show File 備份。
2. 按「停止廣播」，在啟動服務的終端機按 Ctrl+C。若 OSC 橋接也在執行，一起停止。
3. 到 Tools 最底下的 GitHub 專案連結，選 Code → Download ZIP。
4. **解壓縮到新的資料夾**，先保留舊版資料夾供回復；不要把舊版 node_modules 或 dist 複製過去。
5. 在新資料夾雙擊 Start-LAN-Windows.cmd。它會安裝該版本的依賴、重新建置網頁並啟動服務，這次需要網際網路。
6. 主控重新整理原本的 `http://127.0.0.1:8789/`，開啟廣播，讓接收端掃描新的 QR Code。不要同時開著新舊兩份服務。

只要使用相同電腦、瀏覽器／使用者設定檔、協定、主機名稱與連接埠，本機 Show File 通常仍在；程式資料夾不同不會改變瀏覽器的儲存來源。若換瀏覽器、換埠，或把 127.0.0.1 改成 localhost，請匯入備份。

### 使用 Git 安裝

完成備份並停止廣播／服務後，在專案資料夾執行：

```sh
git pull --ff-only
npm ci
npm run lan
```

若 git pull 提示本機修改或無法 fast-forward，先保留修改並處理差異，不要使用 reset --hard 強制覆蓋。`npm ci` 會依新版 lockfile 安裝依賴；單純重新開啟啟動檔不會幫 Git 下載新程式。

### 這次 Q Mark 更新特別注意

此次同步服務的封包上限由 16 KB 提高為 8 MB，以容納 Q Mark 清單。**僅重新整理網頁不會更新已執行中的 Node.js 程式**，務必停止後重新啟動服務。主控與接收端也需重新整理，新開廣播後分享新連結。

更新後先測試「新增 Q Mark → 修改備註 → 刪除 → 手機重新整理」，確認都能同步，再用於正式演出。區網房間會在服務重啟後清除，這是正常行為。
